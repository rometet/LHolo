# LHolo EasyPlace: 階段の任意方向設置の安定性改善

対象: Minecraft for Windows 1.26.51.01 / LeviLamina 26.51.5
基準コミット: 1ecb586（模様入りテラコッタ・フェンス接続・持ち替え改善を含む）

## 現象と確認事項
直近の LHolo latest.log に `stairQueued` と `stairPlanFail` の両方が記録されていた。これは向きのある階段が配置計画を通る場合と、計画上拒否される場合の両方があることを示すが、個々の拒否の原因までは確定できない。
設置送信には追加の競合条件があった。階段の要求ピッチ・ヨーと PlayerAuthInput の現在の値が一致した瞬間には回転の事前送信を省略していたが、その入力がサーバーにとって初めての新しい向きである可能性がある。

## 修正
- 階段の設置のみ、見た目の向きが一致していても、通常の PlayerAuthInput を**異なる2 tick**で向き同期として先行送信し、次の新規 tick で設置トランザクションを付加。
- 別のネイティブ操作が先に入力を所有した場合には**階段を含む同期中の要求の予備送信状態を破棄**。同じ tick を2度数えない。
- 認証済み配置プランの上下半分・四方向に関する厳密な vanilla 予測チェック、実サポートブロック必須の条件を維持。生ブロック状態を書き換えない。
- 階段ではない向き付きブロックは、既に正しい向きのときの同期待ち省略を維持。Praxisの外部FlexibleBlockPlacementプロトコルは変更しない。

## 検証
- Executor 実装fixture: 3228/3228 PASS。階段の向きと上下チェックは既存の全32組を含む。
- BDS packet送信body fixture: 179/179 PASS（階段同方向でも2事前tick、操作割り込み後の再同期を追加）。
- ローカル回転受信 body fixture: 50/50 PASS。
- Windowsネイティブ Release DLLビルド: PASS。
- 実BDS・ローカルワールドにおけるブロック確定結果は未検証。回転送信成功とサーバー上の設置確定は別。

## 実機テスト
Minecraftを終了して `Deploy-EasyPlace-Test.ps1` を実行。失敗や違和感があればゲーム終了後 `Rollback-EasyPlace-Test.ps1` で戻す。
テストワールドのコピーで、階段の上下×4方向を、視点を動かさずに順番に設置。正しい向きで置けたか、アイテムが二重消費されないか、ワールドにブロックが無いのに設置不能でないかを確認。
支持ブロックが必要な位置（上下逆向きの階段を空中へ設置など）は vanilla の配置制限が残る。そこまで強制配置する変更はしていない。
