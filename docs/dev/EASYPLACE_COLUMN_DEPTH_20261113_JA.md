# Easy Place 縦方向連続設置（検証用・未リリース）

## 目的と実装境界
- 主モードは Easy Place。Manual・Range には今回の下段自動探索を適用しない。
- UI `実験的機能 → Easy Place 縦方向の設置段数` は 1（無効/旧動作）から 4。
- Y/BottomToTop/TopToBottom 軸の設計図だけが対象。描画範囲は変更しない。
- まだ設置されていない **可視の最上段** を狙った際は従来通りその段を設置する。
- 上段が完成（または設置送信済みで500ms以内）の場合、可視の上段セルを基準に同じ XZ の下 1〜3 段を順に探索。既に設置済み・送信済みのセルを飛ばし、サーバー到達距離と公式 Block::getPlacementBlock 予測、支持面、アイテム／補助値一致を既存 executor で検証する。
- 現行の送信上限は原則 **1ブロック/Tick**。Java Tweakeroo の configurable multiple-per-tick は今回まだ未実装。20TPS なら理論上およそ 20回/秒。これは実機での受理ブロック数ではない。

## ローカル単体検査
- `xmake r LHoloLogicTests`: 単一レイヤーの `indexAt` が下段を隠し、`indexAtAnyLayer` のみが参照できること、範囲外を拒否すること、段数 1～4 のクランプを確認。
- CI build.yml の全対象を PASS させる。これだけではサーバー設置の正しさは証明できない。

## BDS 実機受入（使い捨てワールド）
1. 元のワールドと mods/LHolo をバックアップ。Easy Place のみ有効、単一Yレイヤー、設置段数=1。石の4段壁を見下ろし、上1段以外に設置されないこと。
2. 同じ壁を段数=4で試す。最上段のホログラムに照準を合わせて上段設置後も視線を保持し、最大3段下まで順に埋まること。各段の設計図／ワールド一致と正味のアイテム消費を確認。
3. 別列に視線を動かす。設定深度を超える5段目や他列には置かれないこと。ワールドに既存ブロックがある段や設計図に空白の段を飛ばすこと。
4. 欠品・別材料の混在・バックパックからのスワップ・ホットバー満杯・クリエイティブ/サバイバルを試す。拒否／未反映のブロックを500ms以降に重複消費させないこと。
5. 階段、上下スラブ、ドア、トラップドア、ホッパーなど向き付き／2セル式は別途検査。送信済み≠BDS反映済みなので、PacketSent だけで PASS としない。
6. Y以外の材料別／Xレイヤーでは縦補助を発動しないこと。メニュー、ワールド変更、転送中、リロードなどで誤実行しないこと。
7. 同一環境で20TPS/低TPS/ネットワーク遅延条件の、成功設置数/秒・重複・拒否率を計測。Java版 fastBlockPlacementCount=1 のベースラインと比較する。

## merge条件
- CI全緑
- 本番同一構成の BDS 実機で、4段 × 複数列・材質違い・向き付きの結果が一致
- 想定外の設置、アイテム二重消費、ログアウト、クラッシュ、desync が0
- 「Java FastBlockPlacement と同速」の主張は成功設置数/秒の比較後に限定する

## ロールバック
- 設定を1に戻すと追加の下段探索が無効になる。
- 問題があれば PR をマージせず作業ブランチのみ破棄。既存配布 DLL は変更しない。
