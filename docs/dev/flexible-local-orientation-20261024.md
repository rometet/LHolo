# FlexibleBlockPlacement：ローカルで全て同じ向きになる不具合の修正

実施日：2026年10月24日（JST）
対象：Minecraft for Windows 1.26.51.01 / LeviLamina 26.51.5
結果：修正版のPraxisCompanionとLHoloを導入し、ローカルワールド内の実配置とブロック状態を確認。

## 原因の再現と修正

以前の送信処理は、選択領域に応じてPlayerAuthInputのmRotとmInteractRotationを変更していた。しかしローカルの統合サーバーが実際のブロック設置を処理する時点では、ServerPlayerの元の向きが参照されていた。送信パケット内の数値だけを確認する試験では、この差を検出できなかった。

専用テストワールドで、プレイヤーは概ね南を向いたまま中央・左・右を選んだ。ログ上の要求yawは180 / -90 / 90度に分かれていたが、修正前の3個のオブザーバーは全てfacing_direction=3だった。これは実際の/testforblockで確認したもので、ローカル表示だけの推測ではない。

修正では、既に受理された1回の設置にだけ短時間有効な記録を作り、ローカルサーバーのItemUseInventoryTransaction::handleで対象を厳密照合する。対象が一致した間だけServerPlayerの設置計算用の向きを要求値にし、通常のMinecraft設置処理を一度呼び、終了・例外時に元の向きへ復元する。ブロックを後からsetBlockで回転させる処理ではなく、通常の設置・消費・検証経路を利用する。クライアントのカメラは変更しない。

照合条件にはプレイヤーRuntimeID、クライアントとは異なるサーバー側プレイヤー、ディメンション、主手、設置操作、選択スロット、アイテムID/補助値/個数、対象座標、面、クリック位置、発信位置、支持ブロックIDを含む。記録は最大8件、250ms、有効な一致で一度だけ消費される。

別の不具合として、期限切れ・入力世代の変わった予約が連携状態取得時に残り、他の配置処理が使用中だと報告される問題も修正した。こちらは修正前8件中4失敗、修正後8件全合格で再現を確認した。

## ローカル実機結果

## 残る制限

今回確認したのはローカルのクリエイティブで、オブザーバー3方向、支持面ありピストン2方向、通常設置の対照試験。BDS/マルチプレイヤー、サバイバル消費、階段・トラップドアの全状態、全ての回転・Offset・Adjacentの組合せを実機で完了したとは主張しない。既存の保持キーや必要な支持条件は変更していない。

配置試験は専用コピーで行った。操作途中には既存のR17テストワールドが一時的にロード・保存されたが、そこでは設置・fill等の試験を行っていない。このため既存ワールドが完全に一切書換えられていないとは扱わない。BDSや他の開発プロセスの停止、セキュリティ設定変更は行っていない。
